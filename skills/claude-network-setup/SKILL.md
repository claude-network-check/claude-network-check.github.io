帮助用户建立可验证的网络路径。根据实际出口和连接证据判断结果，不以第三方检测分数代替验证。

使用 [操作流程](references/workflow.md) 调查、修改和验证；创建配置时参考 [Mihomo 模板](assets/mihomo.template.yaml)。模板含未填写项，不能直接部署。

## 确定范围

- 确认操作系统、客户端和内核版本、配置来源、目标出口及授权修改范围。
- 不固定国家、城市、供应商、网卡编号、代理端口或用户目录，读取实际环境后决定。
- 区分海外中转、固定出口、应用 API 网关、系统代理、TUN 和浏览器策略。
- 用户未要求删除 API 网关、重置应用设置或调整地区语言时，不自动执行这些操作。
- 有其他 VPN 或复杂内网时，记录共存约束；此技能不提供公司网络部署模板，不擅自改动其路由或解析器。

## 实施原则

- 只输出相关字段，隐藏密码、令牌、订阅 URL、认证头和账号。修改前备份；备份与凭据留在本机，不打入公开包。
- 找到实际配置链，包括订阅、全局覆写、脚本和运行时文件。修改持久来源，不能只改会被覆盖的运行时文件。
- 中转是可选项。用户要求探测经代理时，禁止进行绕过代理的公网对比；改动当前连接前考虑工具自身网络依赖。
- Mihomo 中用出口节点的 dialer-proxy 引用中转。保留服务商必需的协议与 TLS 参数，不为连通默认关闭证书验证。
- 明确批准的直连规则在前，MATCH,ISP-EXIT 在后；不自动加国家整体直连。关键词规则范围更广，应符合用户选择。
- 用户需要 TUN 时，启用后验证无显式代理的连接确实进入 TUN。系统代理和 TUN 不必同时开启，不能保证其他 VPN 和所有协议无条件受控。
- DNS 和业务连接分别验证。避免 DNS 需要代理、代理又依赖该 DNS 的启动循环。
- 对未知浏览器先确认应用标识和策略支持。逐 Profile 偏好不等于未来 Profile 自动继承。

## 验证和交付

1. 记录脱敏基线，一次处理一类问题。
2. 检查语法、节点引用、规则顺序及 DNS 启动依赖。
3. 重载后读取内核有效模式、TUN、规则和代理链。
4. 对获准站点查看连接元数据与实际公网出口；没有实测的项目标为未验证。
5. 检查浏览器策略页面和有效偏好，必要时进行有限时长的 WebRTC ICE 检测。
6. 用户需要时，在实际 Profile 中检查 IPPure 分项。已达成验证目标、剩余问题超出本地配置范围，或重测没有新证据时停止；不围绕分数无限改设置。

报告改动、实测、限制、重启或新终端需求及回滚位置。语法通过不等于联网成功；低分不代表官方认可、账号安全或可用性保证。
